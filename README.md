# 新闻视频自动剪辑流水线

> 输入一条新闻原片，输出一份可直接编辑的剪映草稿：AI 写分镜、AI 配音、自动出数据图、自动配画面。

一条把"新闻原片 → 带字幕的成片草稿"全流程自动化的流水线。原本需要人工完成的分镜撰写、旁白录制、数据图表、素材搜集、剪辑拼接，压缩成**一条命令**。

> 产出的是**剪映本地草稿**（可在剪映中继续编辑），不是渲染好的 mp4。这样保留了后期调整的余地。

---

## 实测结果

用一条 1,781 秒（102MB）的财经新闻原片跑完整流程：

| 项 | 结果 |
|---|---|
| 输入 | 1,781 秒原片 |
| Whisper 转写 | 909 个文本段 |
| 大模型分镜 | 输入 2,997 字符 → 输出 1,165 tokens，耗时 7.2 秒 |
| 输出 | **217.4 秒（3.6 分钟）**成片草稿 |
| 结构 | 片头 + 6 个内容模块 |
| 轨道 | 视频轨 / 标题轨 / 字幕轨（三轨齐全） |
| 人工干预 | 从十余步手工操作 → 改 4 个配置项 + 跑一条命令 |

## 八个环节

```
[1/8]  step1_genplan.py          大模型读转写文本，输出分镜（模块数/每段取自原片哪个位置/时长/旁白）
[2/8]  step2_tts.py              edge-tts 合成旁白音频（新闻腔 + 数据腔两种声线）
[3/8]  gen_data_videos.py        把分镜里的数据点渲染成数据图动画 mp4（Matplotlib → FFmpeg）
[4/8]  merge.py                  数据图与 B-roll 素材按旁白时长对齐合并
[5/8]  step_studio_filter.py     模板匹配识别演播室画面区域并裁掉，只留新闻主体
[6/8]  step3_download.py         Pexels 按关键词补网图素材
[7/8]  step_compose_news.py      新闻片段 + 本地素材 + 网图，共用同一条旁白轨合编
[8/8]  step5_full_v2.py          生成剪映草稿（视频/标题/字幕三轨）
```

`run_all.py` 按顺序调起全部 8 步，任一步失败即中止并报出是哪一环。

## 几个值得说的技术点

### 1. 大模型在流水线里的角色是"导演"，不是"文案"

输入是 3,000 字左右的转写文本，输出的是一份**结构化分镜**：

```json
{
  "modules": [
    {"title": "...", "src_start": 12.4, "src_end": 38.1,
     "narration": "...", "data_points": [...], "broll_keyword": "..."}
  ]
}
```

关键在约束：要求它**只能从给定时间轴里选片段**，不能凭空编时间点。否则生成的计划无法映射回原片，整条流水线会断。

### 2. 音画不同步：FFmpeg 的时间基不一致

拼接时出现音画漂移，排查发现各段素材的 timebase 不同（有的是 1/90000，有的是 1/1000）。**统一到 `fps=30, timescale=30`** 后解决。

这类问题不看 FFmpeg 的 `-vsync`/`-r` 参数文档是查不出来的，只能靠对比输出帧与原片时间戳定位。

### 3. 演播室画面裁剪靠模板匹配

新闻原片通常是"主播画面 + 内容画面"的画中画布局。硬编码裁剪坐标不可行（不同来源布局不同），改用模板匹配自动定位演播室区域,再按边界裁掉。

### 4. 转写缓存

30 分钟音频用 Whisper base 转一次要几十秒，但调分镜参数时要反复跑。加了内容哈希缓存,第二次几乎秒出。

### 5. 去水印

`delogo_video.py` 用 FFmpeg 的 `delogo` 滤镜处理素材角标,可配置区域。

### 6. 画质不将就

缩放用 `lanczos`（默认 bicubic 会糊）,CRF 从 23 降到 18。代价是文件变大,但新闻类素材以文字和图表为主,压缩痕迹很明显,值得。

## 怎么跑

```bash
pip install -r requirements.txt
# 另需：FFmpeg、剪映专业版（草稿目录需可写）

# 改 run_all.py 顶部 CONFIG 里的 4 项：
#   MATERIAL_FOLDER  新闻原片所在目录
#   REQ_FILE         需求/分镜文件
#   DRAFT_NAME       草稿名
#   BOX_DIR          B-roll 素材箱

python run_all.py
```

跑完打开剪映 → 本地草稿 → 找 `DRAFT_NAME` 对应的项目。

## 已知局限

- **产出草稿而非成片**：需要在剪映里手动导出。这是有意的取舍——草稿格式保留可编辑性。
- **BGM、转场、分屏、画中画未接入主流程**：`effects_engine.py` 有实现,但没有接到 `run_all.py` 的 8 步里。
- **分镜质量依赖大模型**：一次生成不满意就要重跑第 1 步,没有做多候选采样。
- **素材源受限**：网图只接了 Pexels,且关键词由大模型给,偶尔会跑偏。
